## Timing and recovery

The existing passive view reports paint; policy/queue and Cubit own selection, timing and transitions. Each displayed beat gets one 2500ms timer. Rebuilds do not reset it, late timers advance at most one beat, and an unpainted candidate is not marked used. A slow vote save does not add a second odd-choice hold.

Ready data normally interrupts immediately. Only an already-painted setup owes a punchline plus its complete beat. A ready report does not start an unshown joke or Overtime line. Failure/timeout interrupts immediately, including a failed next offer; retrying the offer does not repeat the vote/model call. Flow revision checks guard read/reveal completions after restart or cancellation.

The queue retains its tap context through save → final-writing transitions. Only six answered choices plus actual final-writing state enable Overtime. Four-choice early completion and earlier exhaustion stay outside it. The twelve approved lines play once in source order; exhaustion holds the last line and writing/activity label. Restarts keep owner/interview-scoped displayed-copy history; unexposed copy is not consumed.

The fallback JSON includes and validates the current metadata and complete Overtime pool. A stale/unsupported server payload keeps that fallback, rather than silently restoring old pacing. The once-per-launch refresh and in-flight copy snapshot remain unchanged.
